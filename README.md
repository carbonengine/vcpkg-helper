# TLDR; How & When to use this tool
Often times, game-team developers will be working on custom versions of carbon components EG

trinity, audio, desity etc . . . 

Often, a new version of carbon engine will be released and be copied up to the perforce stream/branch you’re working in. You will need to change the vcpkg configuration in your customized component, and re-build to get it working in the branch again. This may be because for instance, versions of various dependencies have now changed.

This tool makes that upgrade process a lot easier:
1. Identify what version of the carbon engine has been released to your branch (`vendor/github.com/ccpgames/carbon-port/[VERSION]`)
2. `buildtool target path/to/my/customized/component/project -g git@github.com:ccpgames/carbon-port.git refs/tags/[VERSION]`
3. The necessary changes to the vcpkg configuration (`vcpkg.json` & `vcpkg-configuration.json`) will now be sitting unstaged in your customized component project.

# BuildTool

BuildTool helps you match your vcpkg configuration with a different vcpkg build tree outside of your project which you don't want to / can't depend on through vcpkg. This may be because  the target build-tree is very large and you don't require all of it to build your project, or because it has already been built and you can't / don't want to replace those binaries.

This can help in situations where you want to build a component in isolation, but need to make sure it's compatible with a binary that is also built through vpckg and may share your dependencies.

Usage information can be printed with `-h` or `--help`

```
Usage: buildtool [--help] [--version] {generate,lock,target}

Optional arguments:
  -h, --help     shows help message and exits 
  -v, --version  prints version information and exits 

Subcommands:
  generate      
  lock          
  target   
```

# Usage Modes

There are a few different ways to use this tool.

Each way offers increasing levels of guarantees that your project will be ABI compatible with the target project build. 

### target

```terminaloutput
Usage: buildtool target [--help] [--version] [--spdx VAR] [[--local_target VAR]|[--git_target VAR...]] path

Positional arguments:
  path                Path to the root of the project you wish to configure to the target configuration [nargs=0..1] [default: "."]

Optional arguments:
  -h, --help          shows help message and exits 
  -v, --version       prints version information and exits 
  -x, --spdx          Path to the root directory containing SPDX files to produce version pins. Optional 
  -l, --local_target  Path to a local project you would like to target your dependency tree to EG -l /path/to/target/project 
  -g, --git_target    Git URL and ref of project you would like to target your dependency tree to: EG -g https://github.com/carbonengine/scheduler.git refs/tags/v1.6.0 [nargs: 2] 

```

The simplest way to use buildtool is to have it merge your vcpkg.json & vcpkg-configuration.json files with that of a different project, ensuring your project is compatible with that one.

```terminaloutput
./buildtool target /path/to/my/project/root -g git@github.com:org/other_project.git
```

This will change the vcpkg.json and vcpkg-configuration.json files in  `/path/to/my/project/root` to ensure that 
1. You are using the same baselines for all your configured registries in your vcpkg-configuration.json file as  `other_project.git` does
2. You are using all the same version overrides in your vcpkg.json file as `other_project.git` does 

This is not however completely foolproof. As your projects dependencies may cause the versions of shared dependencies to be raised compared to `other_project.git` 
This also does not guarentee that you will use the same vcpkg triplet & toolchain configuration as the target project.

If you have access to the `vcpkg.spdx.json` files generated by the target build, you can use them to generate version overrides in your vcpkg.json file on top of what is contained within the `vcpkg.json` file of `other_project.git` 
```terminaloutput
./buildtool target /path/to/my/project/root -g git@github.com:org/other_project.git -x path/to/root/of/spdx/files
```

This will search recursively for any and all spdx files contained under the path specified in `-x` and pin all dependencies found there to their corresponding versions as overrides in your `vcpkg.json` file.
This guarantees that you will NEVER use any version of any shared dependencies other than the ones specified in the spdx files. However, this may cause problems if a dependency your project relies on requires any other version of one of these shared dependencies.

### Lock & Generate
```terminaloutput
Usage: buildtool lock [--help] [--version] [-o VAR] [--copy-directory VAR]... [--env VAR...]... path

Positional arguments:
  path                  the path to the cmake build directory you want to produce the lockfile for 

Optional arguments:
  -h, --help            shows help message and exits 
  -v, --version         prints version information and exits 
  -o                    output filename [nargs=0..1] [default: "vcpkg_overrides_template.json"]
  -c, --copy-directory  Specify extra directories to recursively encoded (any overlay triplet directories will be automatically recursively encoded) [may be repeated]
  -e, --env             name and value of an environment variable needed for the build <NAME> <VALUE> [nargs: 2] [may be repeated]

```

```terminaloutput
Usage: buildtool generate [--help] [--version] [-p VAR] [--local_dep VAR...]... [--git_dep VAR...]... [-i VAR] path

Positional arguments:
  path             The path to the lockfile you want to use to generate your configuration 

Optional arguments:
  -h, --help       shows help message and exits 
  -v, --version    prints version information and exits 
  -p               Path to the root of the cmake project you want to generate a configuration for [nargs=0..1] [default: "."]
  -i               If set, the generated preset 'inherits' field will be set to this [nargs=0..1] [default: ""]
```

Another way to use this tool, is to have it generate a lockfile containing all vcpkg configuration used to generate a build tree.
This lockfile can then be used later on by this tool to generate temporary vcpkg & cmake configuration to ensure your project is ABI compatible with the target project.

1. Build the target project, and run the buildtool against the cmake build folder:
```terminaloutput
./buildtool lock path/to/cmake-build-dir
```
This will generate a lockfile called `vcpkg_overrides_template.json` by default.

2. Run the buildtool against this lockfile to generate a temporary vcpkg configuration contained in its own directory, along with a CMake preset named `generated-preset` inside a `CMakeUserPresets.json` file which you can use to build your project.
```terminaloutput
./buildtool generate path/to/vcpkg_overrides_template.json
```
```terminaloutput
cmake --preset generated-preset
```

if you need the generated preset to inherit from any other available preset, see the `-i` option for this command
